# 祀音运维与源码发布交接

核对日期：2026-11-06。项目根目录 <PROJECT_ROOT>。面向后续维护、开发和源码发布的 Agent。

## 1. 接手先确认什么

读取根目录 README.md、AGENTS.md 和 docs/接入规范。当前目录同时放着代码、模型、运行时、用户数据和发布包；本次交接未创建 Git 仓库、设置远程仓库或上传任何文件。后续开始上传前，重新核实目录中的 .git、远程地址和用户指定的目标仓库。

桌面快捷方式“祀音”目前指向 <PROJECT_ROOT>/祀音.exe。如安装了发布版，默认安装目录是用户 LocalAppData/Programs/SiVoiceWorkbench，内部英文目录名为兼容升级保留。开发副本和安装副本使用同一组端口，不能同时运行两套服务。

## 2. 日常运行与只读检查

启动：双击项目根目录祀音.exe，等服务就绪。后台顺序为文本 sidecar → 引擎 → 加载音色 → 网关。不要在界面启动期间另跑一套启动脚本。

本机状态：

~~~powershell
Invoke-RestMethod 'http://127.0.0.1:9888/api/status'
Invoke-RestMethod 'http://127.0.0.1:9881/v1/health'
Get-NetTCPConnection -State Listen -LocalPort 9880,9881,9882,9888 |
    Select-Object LocalAddress,LocalPort,OwningProcess
~~~

网关健康接口 HTTP 200 不代表引擎就绪，要检查 ok、engine、voice。监控 state 有时可能滞留 loading，需结合端口与实际健康结果排查，不要据此重复拉起服务。PID 文件也不是进程身份的充分证据。

桌面默认端口为 9888，有旧服务占用时自动避让至 9898 或空闲回环端口。先读 app/run/desktop-server.json 的 port，再访问对应 /api/workbench/instance；application 必须为 siyin-workbench、protocol 为 1、root 为当前安装的 app 绝对路径。仅有 /api/status 响应不足以识别桌面后台。上面的固定 9888 检查命令需要按实际端口替换。内部工作台请求都使用同一实际端口；网关仍为 9881。

密钥只检查“是否设置”，不要输出整个配置：

~~~powershell
$cfg = Get-Content -LiteralPath '.\app\services\config.json' -Raw |
    ConvertFrom-Json
[pscustomobject]@{
    Host = $cfg.gateway.host
    Port = $cfg.gateway.port
    ApiKeyConfigured = [bool]$cfg.gateway.token
}
~~~

退出：关闭窗口是收托盘；“退出应用”只关桌面端。需要停模型时用“停止服务并退出”。监控本身仍可能驻留，不能把“无窗口”当作“已释放模型”。

维护程序可运行下方现有停止入口，但应先确认没有用户任务：

~~~powershell
& '.\app\python\python.exe' '.\app\desktop\stop_owned.py'
~~~

它调用带身份检查的现有停止控制。不要按 python.exe、pythonw.exe、gsv_server.exe 等进程名全局杀进程，也不要仅凭端口占用就终止进程。旧 start_all.bat/start_monitor.vbs 为兼容入口保留，日常优先桌面统一入口；迁移电脑时检查旧脚本和文档是否还有机器路径。

## 3. 配置、数据与备份

| 位置 | 维护要点 |
|---|---|
| app/services/config.json | 网关 Key、路径、音色/合成参数；本机私有 |
| app/config/gsv.env | 旧脚本运行选项；不是当前主要 API Key 来源 |
| app/models/voices/*/manifest.json | 模型/参考音频路径；含本机路径，不直接作为公开示例 |
| app/out/workbench/library.sqlite | 任务与作品索引 |
| app/out/workbench/<任务ID>/ | WAV、分段、live PCM、导出文件 |
| app/out/workbench/identities/ | 历史头像等持久资源 |
| app/out/mcp_*.wav | MCP 默认输出，不一定出现在桌面作品库 |
| app/run/*.pid | 临时进程状态，不备份为运行依据 |

备份前暂停派发并等待当前任务结束，关闭实际写入作品库的监控/工作台进程后，整体复制 app/out 和配置；保留 SQLite 关联日志文件（若存在）。在线备份应使用 SQLite backup API，不要只复制正在写入的主库文件。

模型和参考音频也需有可恢复来源。备份目录应在目标目录外，不要在 app/out 内递归备份自身。恢复/迁移时先保留原数据，再让 bootstrap 解析 @APP_ROOT@ 和旧 _app_root，不要全文件替换盘符；用户指定的外部参考音频路径可能有意位于项目外。

参数和参考配置保存后，已启动网关不会自动重读所有值，需要停止并启动服务。正常调优维持语速 0.88、步数 4；先保留用户已有配置，不能用脱敏模板覆盖真实配置。

## 4. 排障与性能

| 症状 | 优先检查 |
|---|---|
| 无窗口 | app/logs/desktop.log；WebView2、pythonnet、单实例窗口是否在托盘 |
| 桌面显示旧服务管理页 | 检查 desktop_server.py 的身份验证与缓存端口，不要仅凭 9888 有响应就复用；桌面启动不应触发浏览器兜底 |
| 服务加载不完成 | 9882/9880/9881 实际健康、模型文件、Vulkan 驱动、端口进程身份 |
| 文本处理导入失败 | app/frontend 和 Python 依赖是否完整；不要用另一版本整个覆盖 |
| 网关 401 | 客户端 Key 与 gateway.token 是否一致，改 Key 后是否重启网关 |
| 网关 429 | 当前并发上限；按 Retry-After 退避，不增开模型进程 |
| 本机可用、局域网不通 | 服务电脑 IP、TCP 9881、防火墙、路由/AP 隔离 |
| 播放空流/断流 | 客户端奇数字节拼接、实际采样率；网关/引擎日志；200 后仍可中断 |
| 不能导出某格式 | app/tools/ffmpeg 编码器、磁盘空间和中文路径；WAV 母版是否完成 |
| 窗口又变 Python 图标 | launch.py 的 before_show 原生 Icon 设置与 si-voice.ico 是否随包存在 |
| 输入框没有右键粘贴菜单 | launch.py 在 WebView2 初始化完成后启用 AreDefaultContextMenusEnabled；pywebview 正式模式默认关闭它，不能靠打开 debug 模式修复 |
| 显存未释放 | 是否仅关闭界面；确认该项目引擎进程是否仍在运行 |

主要日志：app/logs/desktop.log、app/monitor/logs/engine.log / sidecar.log / gateway.log，以及 app/services/gateway/logs 下网关轮转日志。日志也可能含文本、路径、IP 等信息，分享前按实际内容脱敏。

监控历史为有界内存数据，不是永久时序库；正常页面采样与后台采样频率不同。工作台温度达到 80°C 暂停派发后续任务，降到 75°C 恢复；当前任务不强杀，温度不可读不自动控制。这不是整机温控器，也不保证暂停所有外部 API 请求。

不要使用随机数或虚构曲线代替指标。不要把 WebView2 工作集合计、整机内存占用和模型显存混成一个数字。

## 5. 源码修改与验证

前端源码是 app/ui/src，不是 app/frontend。嵌入式 Python 是运行基线；源码仓库的 requirements.txt 只覆盖桌面相关依赖，不能当成原后端全部依赖清单。

~~~powershell
Push-Location '.\app\ui'
npm ci
npm run build
Pop-Location
& '.\app\python\python.exe' -m unittest discover -s '.\app\tests' -p 'test_*.py'
~~~

桌面读取 dist，改 src 但没重新构建不会更新运行页面。当前 package.json 没有 dev 脚本，开发预览可在 app/ui 下执行 npx vite；完整工作台仍依赖 9888 的本地接口与会话，不是单独启动 Vite 就能完整使用。

真实后端就绪、可写作品且用户没有任务时，可选择运行：

~~~powershell
& '.\app\python\python.exe' '.\app\tests\api_smoke.py'
& '.\app\python\python.exe' '.\app\tests\mcp_smoke.py'
& '.\app\python\python.exe' '.\app\tests\release_integration.py'
~~~

这三项不是只读测试：api_smoke 会创建作品并导出，mcp_smoke 会合成、保存参数/参考配置并切换音色，release_integration 会创建超过 2000 字的长音频并测试队列等。逐项阅读脚本、确认影响后执行，不要在日常健康检查时自动跑全套。

当前已核实二十六项单元测试（含桌面服务身份、端口冲突、局域网认证/代理/开关、独立安装配置）与构建；先前真实 GPU 验证记录见发布验收文件。长期稳定性和严谨性能基线仍有待补齐，不要把旧记录当作本次改动全部重新测试。

## 6. 重新编译和打包

现有总入口：

~~~powershell
& '.\packaging\build.ps1'
~~~

它执行：前端正式构建 → C# 桌面启动器编译 → 单元测试 → Inno Setup 分卷安装包。C# 编译先输出临时英文名，再归档旧入口、替换祀音.exe；归档不是最终发布包。涉及桌面行为变更时需重启桌面实际验证，但不要连带强停用户正在执行的语音任务。

构建工具：

- C#：从 WINDIR 查找 Framework64/v4.0.30319/csc.exe，不依赖系统盘为 C:。
- Inno Setup：优先 SIYIN_ISCC 环境变量，其次 PATH 和常见安装位置；本机为 D:/GitSoft/Inno Setup 7/ISCC.exe。
- build.ps1 向安装脚本传入实际项目根目录；直接编译脚本时 SourceRoot 默认从脚本位置解析。
- 构建临时目录 packaging/tmp。
- 打包基线在 packaging/staging；此处配置使用 @APP_ROOT@，Key 应为空，由每台安装的 bootstrap 生成。

换机器后安装构建工具或设置 SIYIN_ISCC。build.ps1 自动刷新安装器/分卷的 SHA256SUMS，但不自动重建 staging 或运行全部真实 GPU 集成测试。不同版本修改 AppVersion、OutputDir、OutputBaseFilename 和发布说明；稳定 AppId 不随意更改，以免升级关系丢失。

安装脚本还会打包 app/config/gsv.env，发布前检查它是否含个人设置或后来新增的秘密。模型、参考音频与头像也要按实际分发范围检查。安装器保留现有 config/manifest，新安装初始化独立 Key，不用开发机配置替代 staging。

当前输出 release/祀音-1.0.0：

- 祀音安装包-1.0.0.exe。
- 祀音安装包-1.0.0-1.bin。
- 祀音安装包-1.0.0-2.bin。
- SHA256SUMS.txt、使用说明.txt、验收记录.md。

总量约 2.9GB，三个程序/分卷文件必须一起分发。用户完整下载到同一目录，再运行 EXE。ZIP 分发先完整解压；GitHub Release 可分别上传三个文件。源代码和安装包分开交付。

所有文件构建结束后再更新校验：

~~~powershell
$releaseDir = Join-Path (Get-Location) 'release\祀音-1.0.0'
$lines = Get-ChildItem -LiteralPath $releaseDir -File |
    Where-Object { $_.Extension -in '.exe','.bin' } |
    Sort-Object Name |
    ForEach-Object {
        $hash = (Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash.ToLower()
        "$hash  $($_.Name)"
    }
$lines | Set-Content -LiteralPath (Join-Path $releaseDir 'SHA256SUMS.txt') -Encoding utf8
~~~

变更版本号后同步修改路径。构建完成不等于安装验证完成，版本记录写清实际执行了什么。当前安装包未签名，需要的系统组件/显卡条件见 README。

## 7. 上传源码的范围

在准备好的源码副本中，按明确文件清单暂存；不要直接 git add 整个完整运行目录。

### 项目自有代码与文档

通常纳入：README.md、AGENTS.md、本文件、docs/接入规范、开源说明、app/ui 的 src/public/index.html/package.json/package-lock.json/tsconfig 与 Vite 配置、app/desktop 源码与 requirements、app/monitor/monitor.py、app/services 源码、app/tests、适当的启动脚本、packaging/build.ps1 和 installer.iss。

app/frontend 包含上游文本处理代码，提交前核对来源并保留相应许可/归属。app/engine 当前只有预编译组件，没有对应 C++ 源码树；应记录准确上游地址、版本/提交和复现来源，不能宣称已经上传整个引擎源码。

UI 静态资源、appico.png 和 ICO 中含参考人物图。生成山水提示词位于 app/docs；用户提供素材的来源和授权还未完整登记。公开仓库与二进制分发是否可包含这些资源需要按已确认授权处理，不用“代码开源”替代素材确认。

### 排除的私有和大文件

- app/services/config.json、其备份/临时文件；真实 gateway.token；任何 .env、证书或隧道凭据。
- app/out 全部：SQLite、用户文字、WAV、参考导入与历史头像等。
- app/run、所有层级 logs、*.log、测试产生的音频、个人备份。
- app/models 模型权重与原始参考音频；真实 manifest 的本机路径。
- app/python、app/tools/ffmpeg、app/engine 的二进制运行包。
- app/ui/node_modules、通常可重建的 dist、__pycache__、*.pyc。
- release 全部安装包，packaging/tmp、verification-archive、构建日志与测试安装目录。
- 机器专属快捷方式 .lnk、既有 EXE 产物，以及可能包含秘密的历史文档/测试快照。

不要用全局 *.json 排除规则：package.json、锁文件、TypeScript 配置和工具 schema 都属于必要源码。应给真实 config.json 和本机 manifest 做精确规则。当前根目录尚无统一 .gitignore，后续上传任务需创建并检查它。

## 8. 网络维护与下一步

本机网关保持 127.0.0.1:9881；可开关的局域网入口由 app/desktop/lan_access.py 提供，默认 9890，同时提供 Key 登录后的工作台和语音 API。新安装局域网默认关闭；本开发机已开启。地址由 psutil 读取实际网卡，不依赖开发机 IP；配置在 network.lan_enabled/lan_port。工作台仍在回环地址，局域网入口与它共用同一组任务和模型，不额外加载模型。

在设置页开启局域网会按需要申请管理员授权，创建该安装目录专属的 Windows 防火墙规则，限定程序路径、TCP 端口和 RemoteAddress=LocalSubnet，适用于当前网络配置文件。关闭局域网开关停止监听并使网页会话失效，规则保留供再次开启；改变端口后重新配置规则。Windows 标记为 Public 的家庭 Wi-Fi 不会被程序擅自改为 Private。当前规则已实际验证放行 9890/LocalSubnet，已通过本机局域网 IP 验证网页登录、Key 鉴权和真实 WAV 合成；尚未从另一台设备端到端检查。

首次升级会把历史 0.0.0.0:9881 收敛为回环网关，仅在确认无活跃请求且进程路径属于本安装时重启网关，不重启模型；忙碌或身份不符则显示错误等待处理。原来访问局域网 IP:9881 的客户端需改到设置页显示的入口；本机 API/MCP 地址不变。局域网用户不能通过远程页面修改网络配置或读取 Key。

后续公网拓扑：外部设备 → HTTPS 服务器入口 → 私有隧道 → 已启用的受保护入口（页面和 API），或仅在受保护隧道内连接本机 9881（只要语音 API）。尚未部署隧道/域名/HTTPS；不要标为已完成。参考 API.md 处理鉴权、代理缓冲、Cookie、超时及可信转发地址。MCP 当前仅本机 stdio。

## 9. 维护记录模板

每次维护后简要记录：日期、问题、修改的文件、实际运行的检查、是否重启/重打包、交付物位置、未完成验证和回滚材料。现有验证归档可能含私人数据，只在本地保留，不直接提交到公开仓库。
